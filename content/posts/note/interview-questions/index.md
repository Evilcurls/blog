##  1.当矩阵是百万级规模时，如何用概率论快速判断 \(AB = C\)？

在大规模矩阵计算的场景中（比如 \(n = 10^6\)），直接计算矩阵乘积 AB 再与 C 比较是完全不现实的 —— 毕竟 \(n^3\) 的复杂度会让超级计算机都望而却步。这时候，**概率论方法**就能帮我们在可接受的时间内，以极高的概率完成判断。

当 \(n = 10^6\) 时，直接计算两个 \(n \times n\) 矩阵的乘积 AB，需要执行 \(n^3 = 10^{18}\) 次运算。哪怕是当前最快的超级计算机（每秒约 \(10^{17}\) 次运算），也需要近 10 秒才能完成一次这样的乘法，更别说矩阵存储（单矩阵就需要 \(10^{12}\) 个元素，约 4TB 空间）的压力了。

所以，直接计算 AB 再和 C 逐元素比对，在工程上是**完全不可行**的。

**方法：随机向量检测**

我们利用一个关键的数学逻辑：

- 如果 \(AB = C\)，那么对**任意**向量 都有 \(AB\mathbf{x} = C\mathbf{x}\)；
- 如果 \(AB \neq C\)，那么矩阵 \(D = AB - C\) 是**非零矩阵**，但它的 “零空间”（满足 \(D\mathbf{x} = \mathbf{0}\) 的向量 \(\mathbf{x}\)）是**低维的**，随机选到这样的 \(\mathbf{x}\) 的概率极低。

基于这个逻辑，我们可以设计如下步骤：

**步骤 1：生成随机向量 x**

构造一个 n 维的随机向量  x，比如让每个分量独立服从伯努利分布（取 0 或 1），或标准正态分布 n to (0,1)\)。

**步骤 2：分步计算 (ABx) 和 \(Cx)**

这里的关键是**利用矩阵 - 向量乘法的结合律**，避免直接计算 AB：

- 先算 \(\mathbf{y} = B\mathbf{x}\)（矩阵 B 与向量 \(\mathbf{x}\) 相乘，复杂度 \(O(n^2)\)）；
- 再算 \(AB\mathbf{x} = A\mathbf{y}\)（矩阵 A 与向量 \(\mathbf{y}\) 相乘，复杂度 \(O(n^2)\)）；
- 同时计算 \(C\mathbf{x}\)（矩阵 C 与向量 \(\mathbf{x}\) 相乘，复杂度 \(O(n^2)\)）。

**步骤 3：比较并验证**

- 如果 ABx  不等于  Cx，**可以 100% 确定** AB 不等于 C；
- 如果 ABx=Cx**不能 100% 确定** \(AB = C\)，但可以通过**多次重复检验**（每次换不同的随机向量 x），把 “误判概率” 降到极低。



**方法优点**

1. 计算复杂度的飞跃

直接计算 AB 是 \(O(n^3)\)，而用随机向量检验每次仅需 \(O(n^2)\)（甚至在矩阵稀疏时，复杂度可低至 \(O(n)\)）。当 \(n = 10^6\) 时，\(n^2 = 10^{12}\)，比 \(n^3\) 小了 1000 倍，工程上完全可执行。

2. 可靠性的数学保证

对于非零矩阵 \(D = AB - C\)，其零空间的维度最多是 \(n-1\)（远小于 n 维的全空间）。如果 x是随机生成的（比如服从连续分布），那么 x 落入零空间的概率是**0**；即使是离散分布，这个概率也会随着检验次数的增加指数级下降（比如每次误判概率 1/2，检验 10 次后误判概率就小于 \(1/1000\)）。



## 2.简述中心极限定理

简单来说，中心极限定理讲的是：**如果有一堆独立的随机因素在共同影响一个结果，不管这些因素本身是什么分布，只要它们的影响都不算特别极端，那么这个结果的整体分布最终会趋近于正态分布（也就是钟形曲线）**。

举个例子，假设你要统计一个城市所有人的身高。每个人的身高受到遗传、饮食、运动等很多独立因素的影响。有的因素让身高高一点，有的让身高矮一点。当把几十万人的身高数据汇总后，你会发现这些数据的分布会呈现出中间高、两边低的钟形 —— 这就是中心极限定理在起作用。

再比如抛硬币，单次抛硬币是正面还是反面是随机的，但如果抛很多次（比如 1000 次），记录每次正面出现的次数，你会发现这些次数的分布也会趋近于正态分布。

中心极限定理的价值在于，它让我们在面对复杂的随机现象时，有了一个可预测的 “终点”。不管底层的随机因素多复杂，只要它们相互独立、影响均匀，最终的结果分布都会向正态靠拢。这也是统计学中很多方法（比如假设检验、置信区间）的重要理论基础。



## 3.如何解决机器学习中类别不平衡的问题

在机器学习中，“类别不平衡” 是个很常见的问题。比如在诈骗检测中，正常交易是绝大多数，诈骗交易寥寥无几；在疾病筛查中，健康人群远多于患病人群。如果直接用这样的数据训练模型，模型很容易 “偏向” 多数类，对少数类的预测效果极差。那该怎么处理呢？

### 1. 数据层面：调整样本分布

- **过采样**：对少数类样本进行复制，增加其数量。比如少数类只有 100 个样本，多数类有 1000 个，我们可以把少数类样本复制几次，让它的数量接近多数类。不过要注意，简单复制容易导致过拟合，现在常用的是 “合成少数类过采样技术（SMOTE）”，它会根据少数类样本的特征，合成新的、合理的样本。
- **欠采样**：对多数类样本进行删减，减少其数量。比如从多数类的 1000 个样本中随机选 300 个，和少数类的 100 个样本一起训练。这样能平衡数据量，但可能会丢失多数类的一些重要信息。

### 2. 模型层面：给少数类 “加权”

在训练模型时，我们可以给少数类样本设置更高的权重。比如在损失函数中，少数类样本预测错误时，模型会受到更严重的惩罚。这样模型就会更 “关注” 少数类，提高对它的预测准确率。像决策树、随机森林等模型都支持设置样本权重。

### 3. 评估层面：换个指标看效果

传统的准确率指标在类别不平衡时会失效（比如多数类占 90%，模型全猜多数类也能有 90% 准确率）。这时候可以看**精确率、召回率、F1 分数**这些指标。

- 精确率：预测为少数类的样本中，真正是少数类的比例；
- 召回率：真正的少数类样本中，被模型预测出来的比例；
- F1 分数：精确率和召回率的综合，能更全面地反映模型对少数类的预测能力。

### 4. 算法层面：专门的不平衡算法

有些算法本身就对类别不平衡有较好的适应性，比如**集成学习中的极端随机森林、梯度提升树（GBDT）** 等，它们可以通过组合多个弱分类器，减少对多数类的偏向。另外，“异常检测” 思路也常被用于少数类占比极低的场景，把少数类当作 “异常” 来识别。



## 4. 递归求斐波那契数列的时间和空间复杂度

**时间复杂度**

定义 T(n) 为计算 fib(n) 所需的总计算量。

根据递归函数的定义：
fib(n) = fib(n-1) + fib(n-2)

我们可以得出计算量的关系式：
T(n) = T(n-1) + T(n-2) + 1 (最后的 +1 代表那一次加法操作)

为了简化分析，我们可以忽略 +1，因为我们只关心增长的趋势。
T(n) ≈ T(n-1) + T(n-2)

我们再看 T(n-1):
T(n-1) ≈ T(n-2) + T(n-3)

代入进去：
T(n) ≈ [T(n-2) + T(n-3)] + T(n-2) = 2 * T(n-2) + T(n-3)

T(n) 大约是 2 * T(n-2)。这意味着，n 每减少2，计算量就要翻一倍。这是一种典型的**指数增长**模式。

所以时间复杂度为2^n

## 5.矩阵中的秩代表什么

### 

矩阵的秩是矩阵中行（或列）向量组的极大线性无关组所含向量的个数，它反映了矩阵的线性相关性和空间维度特性。例如，对于一个 m x n的矩阵，其秩 r 满足 0 < r <min (m,n)。秩为 r 意味着矩阵中存在 r 个线性无关的行（或列），其余行（或列）都可以由这 r 个行（或列）线性表示。



## 6.归并排序和快速排序

- 归并排序
  - 思想：分治法，将数组不断分成两半，分别排序后再合并。
  - 时间复杂度：\(O(n\log n)\)（最好、最坏、平均均是）。
  - 空间复杂度：\(O(n)\)（需要额外空间存储合并后的数组）。
  - 稳定性：稳定（相等元素的相对顺序在排序后不变）。

- 快速排序
  - 思想：分治法，选择一个 pivot（基准元素），将数组分成小于 pivot 和大于 pivot 的两部分，递归排序这两部分。
  - 时间复杂度：平均 \(O(n\log n)\)，最坏 \(O(n^2)\)（如 pivot 选择不当，数组已完全有序时）。
  - 空间复杂度：\(O(\log n)\)（递归栈的深度）。
  - 稳定性：不稳定（pivot 交换时可能改变相等元素的相对顺序）



## 龙猫数据

### 项目一

#### 1. 为什么在模型训练时选择 Qwen3-4B？

首先选择开源模型。Mistral、LLaMA 由于预训练语料等原因，原生词表对中文的支持不如中文模型；在中文开源模型中，Qwen 的社区讨论度较高，可借鉴的经验也更多。

在模型版本上，Qwen3.5 默认带有推理标签，可能对后续 RL 阶段造成影响。参数量方面，过小的模型（如 0.6B）在微调阶段更容易出现能力遗忘，而 32B 等大模型在 PPO 阶段对显存和算力的要求又过高。综合中文能力、社区生态和训练成本，最终选择 Qwen3-4B。

#### 2. 增量预训练阶段如何避免灾难性遗忘？

灾难性遗忘是指模型吸收新领域知识后，其他领域，尤其是通用领域的能力发生退化。我的处理思路主要有两点：

1. 使用 LoRA 训练，冻结原模型参数，只引入并训练旁路低秩矩阵，尽可能保留原参数。类似思路还有适用于全量微调的 EWC（弹性权重巩固），但我没有实际尝试过。
2. 混合领域数据与通用数据。训练时，医疗数据和通用数据按 (1:3) 的比例混合，避免模型只接触医疗语料而导致通用能力退化。

#### 3. DPO 的原理是什么？它如何替代 Reward Model？

DPO 直接在偏好数据上优化语言模型。它通过数学重参数化，把奖励函数等价映射到策略模型本身，因此不需要单独训练显式的 Reward Model。

具体来说，DPO 会对比当前策略模型 \(\pi_\theta\) 与冻结的参考模型 \(\pi_{\text{ref}}\)。对于偏好数据中的 chosen（优选回答）和 rejected（劣选回答），分别计算它们在当前模型与参考模型下生成概率的对数比值，再最大化两组比值之间的差，使模型提高 chosen 的相对概率、降低 rejected 的相对概率。

#### 4. PPO 与 GRPO 的原理分别是什么？

PPO 是 RLHF 中常用的强化学习优化算法，通常涉及四个模型：

- Actor：正在训练的策略模型；
- Reference Model：冻结的初始策略，用于计算 KL 约束；
- Reward Model：根据人类偏好给完整回答打分；
- Critic：预测状态价值，用于估计 advantage 并降低策略梯度的方差。

训练时，Actor 根据 prompt 采样回答，Reward Model 给出奖励，并加入当前策略与 Reference Model 之间的 KL penalty，避免策略偏离原模型过远。Critic 预测 value，再通过 GAE 等方法计算 advantage。PPO 使用新旧策略的概率比值和 clipped objective 限制单次更新幅度：

\[
\min\left(r_t A_t,\operatorname{clip}(r_t,1-\epsilon,1+\epsilon)A_t\right)
\]

advantage 为正时，提高对应生成路径的概率；为负时，降低其概率。

GRPO 可以看作 PPO 的简化版本。它移除了 Critic，不再训练 value model，而是针对同一个 prompt 一次采样多个回答，使用 Reward Model 或规则奖励分别打分，然后在组内计算相对 advantage：

\[
A_i=\frac{r_i-\operatorname{mean}(r)}{\operatorname{std}(r)}
\]

高于组内平均水平的回答得到正 advantage，低于平均水平的回答得到负 advantage，之后仍使用类似 PPO 的 clipped objective 与 KL 约束更新策略。GRPO 不需要 Critic，显存占用更低、流程更简单；代价是每个 prompt 需要采样多个回答，而且 advantage 的估计更依赖组内比较质量。

#### 5. DPO 的 reward signal 是什么？

DPO 没有显式训练 Reward Model，但仍然存在隐式 reward。它利用偏好数据中的 chosen 和 rejected 构造偏好信号，通过优化两者的概率差实现奖励学习。从理论推导看，reward 可以表示为当前策略模型与参考模型概率比值的对数，因此奖励信号被隐式地融入了 DPO 的损失函数。

### 项目二

#### 1. POI 搜索失败时，LangGraph 如何处理？

POI、航班、天气等外部服务型 Agent 都依赖第三方 API，可能遇到网络超时、限流、空结果或服务不可用。我不会让单个 Agent 的失败直接中断整个 LangGraph，而是把错误写入全局状态，例如 `error_messages` 或 `node_status`，再通过 conditional edge 判断进入正常流程还是 fallback 流程。

fallback 分为三层：

1. **短重试**：如果是 timeout、连接失败、5xx 等偶发网络问题，重试 2～3 次，并设置单节点超时时间，避免某个 Agent 阻塞整条链路。
2. **备用数据源**：POI 搜索失败时切换到高德关键词搜索、周边搜索或本地热门景点模板；天气 API 失败时切换备用天气服务；航班 API 失败时可返回空候选航班，但继续保留酒店和景点规划。
3. **LLM 降级生成**：如果外部 API 均不可用，让 LLM 根据目的地和用户偏好生成通用推荐，并在前端标记为“参考推荐”，明确其准确度与实时性较低。

整体原则是：外部服务 Agent 属于可降级节点，失败时优先部分返回或降级返回；只有偏好解析、目的地选择、预算校验等核心状态节点失败时，才终止流程。

#### 2. 如何保证 Pydantic 后端与 TypeScript 前端的接口定义不漂移？

类型漂移是指业务迭代时，由于沟通不及时或人为疏忽，前后端的数据结构约束逐渐脱节。解决方法是建立单一数据源（Single Source of Truth）：

1. 后端由 FastAPI 根据 Pydantic 模型自动生成 OpenAPI Schema；
2. 前端在构建阶段使用 `openapi-typescript` 等工具读取该 Schema，自动生成 TypeScript 类型定义；
3. 只人工维护后端这一份模型，前端类型完全由工具派生，从工程流程上避免人工维护两套定义造成的漂移。



## 望石科技

### 1. LangGraph 中的 Agent 如何处理循环？

LangGraph 中，每个 node 执行完都会返回更新后的 state。普通 edge 负责固定流转，conditional edge 则调用路由函数，根据 state 中的字段决定下一步。

例如在预算场景中，`BudgetAgent` 会根据预算是否通过、调整轮次是否达到上限，将状态更新为 `completed`、`adjusting` 或 `failed`。conditional edge 读取状态后：

- `completed`：进入 `END`；
- `failed`：终止流程；
- `adjusting`：把同一份 state 路由回搜索或调整节点，继续下一轮。

因此，循环不是无条件执行，而是由状态、终止条件和最大调整次数共同控制。

### 2. 天气变化或多人需求出现时，如何调整行程？

如果天气信息在首次规划时已经可用，先把行程结构化，再接入天气等外部数据，把天气变化转换成约束条件，找出受影响的行程节点。随后生成替换、调换或缩减等多个候选方案，并通过评分函数选择最优方案。大模型主要负责理解偏好、生成解释和与用户交互，而不是仅靠一条 prompt 重新生成整个行程。

如果行程生成后天气才发生变化，可以设置每 5 小时执行一次的定时检查，只运行天气 Agent（也可扩展到机票变动、预算 Agent）。一旦发现天气会影响户外活动，就主动向用户发送消息并提供调整方案。

> 原评论只记录了天气变化的处理方案，没有补充多人偏好冲突的具体答案。



## 字节跳动 Data 语音

### 1. 简单介绍一下 TTSDS2

TTSDS2 的核心流程是：

1. 使用多个预训练模型提取生成语音、真实语音和噪声参考的特征；
2. 在不同质量维度的特征空间中建立分布；
3. 计算生成语音分布与真实语音分布之间的 2-Wasserstein 距离；
4. 使用噪声参考对距离归一化，使不同特征的尺度更可比；
5. 汇总 Prosody、Generic、Speaker 和 Intelligibility 四类分数；
6. 最终在 system-level 上比较客观分数与人工 MOS 排名之间的相关性。

### 2. TTSDS2 的四个因子分别如何提取特征？

- **Generic**：使用 WavLM、HuBERT 的激活值；
- **Speaker**：使用 d-vector 和 WeSpeaker 提取说话人特征；
- **Prosody**：使用 WORLD 提取的 F0（基频），并基于 HuBERT 提取语速特征；
- **Intelligibility**：使用语音识别模型的激活值，包括 wav2vec 2.0 ASR 和 Whisper Small ASR 的激活值。

### 3. 简单介绍一下 SQ-LLM

SQ-LLM 的出发点是同时解决评价成本和可解释性问题。传统主观听评可信度较高，但成本很高；传统客观指标虽然成本低，却往往只输出一个分数，不能解释问题来自噪声、失真、语速还是连续性。

SQ-LLM 使用具备音频理解能力的语音大模型，通过指令微调完成多维质量评分，并生成自然语言解释。这样，评价结果既包含分数，也能指出具体的质量缺陷。

### 4. SQ-LLM 的训练数据如何构造？

1. 标注人员听取音频并填写结构化问卷，不仅对可懂度、失真度等 8 个维度打分，还标注失真的精确时间戳、说话人性别以及“嘶嘶声”等听感关键词。
2. 使用文本能力较强的大模型，把人工提供的零散信息扩写成连贯的评价草稿。
3. 人工核对并纠错，确保描述忠于真实听感。
4. 再次使用大模型改写文本，生成多种句式变体，最后由人工选出最终版本。

### 5. 类似 Qwen-Audio 的音频大模型如何构建训练数据？音频编码器如何与语言模型对齐？

这类模型通常由音频编码器和语言模型组成。音频先经过基于 Whisper 初始化的编码器，转换为连续音频表征，再作为条件输入 Qwen LLM；语言模型根据音频表征和已经生成的文本，自回归预测下一个文本 Token。因此，它不是先把音频离散为 speech token，而是用连续特征对语言模型进行条件化。

训练数据不仅包含语音识别所需的音频和转写，还覆盖语音翻译、音频描述、情感识别、声学场景分类、音频问答、音乐分析等任务，并统一建模为条件文本生成任务。同一段音频可能对应转写、翻译、情感判断等不同答案，因此必须提供任务条件。原始 Qwen-Audio 使用层级任务标签解决一对多冲突，Qwen2-Audio 则将其简化为自然语言 Prompt。

原始 Qwen-Audio 在多任务预训练阶段冻结 Qwen LLM，只训练音频编码器，通过文本 next-token loss 让编码器学习出 LLM 可理解的音频表示；在 Qwen-Audio-Chat 的 SFT 阶段冻结音频编码器，训练 LLM，使模型获得指令跟随和多轮对话能力。Qwen2-Audio 在此基础上进一步加入 DPO，使用优劣回答对进行偏好对齐。

### 6. CosyVoice 的整体架构是什么？哪些模型会影响最终合成质量？

CosyVoice 2 采用语义与声学解耦的两级生成架构，最后再通过 Vocoder 恢复波形。

第一级是 **Speech Token 生成**。目标文本经 BPE Text Tokenizer 转为文本 Token；在零样本 ICL 模式下，参考语音还会经过基于 SenseVoice-Large ASR Encoder 和 FSQ 构建的 Speech Tokenizer，得到 Prompt Speech Tokens。参考文本、目标文本和 Prompt Speech Tokens 一起构成 Text-Speech LM 的上下文。CosyVoice 2 使用 Qwen2.5-0.5B 作为 Text-Speech LM，通过自回归 next-token prediction 生成目标 Speech Tokens。这一级主要负责内容、文本—语音对齐、隐式时长、停顿和高层韵律。

第二级是 **声学生成**。LM 生成的 Speech Tokens，与参考语音中提取的 Speaker Embedding 和 Reference Mel 一起作为条件，输入 Chunk-aware Flow Matching，生成目标 Mel 频谱。Speaker Embedding 主要提供全局说话人身份，Reference Mel 提供更具体的参考声学信息，因此这一阶段主要决定音色相似度、局部声学细节和自然度。最后由预训练 Vocoder 将 Mel 频谱转换成 24 kHz 波形。

从质量影响看：

- Text Tokenizer、Speech Tokenizer 和 LLM 主要影响内容正确性、发音、时长和高层韵律；
- Speaker Encoder 和 Flow Matching 主要影响音色相似度、声学自然度与细节；
- Vocoder 直接影响最终波形的清晰度、高频细节和失真。

### 7. 如何设计可靠的 MOS 实验？

首先应根据主观评价实验的性质选择方法。评价 TTS 的自然度和真实度时，可以采用基于 ACR 的 MOS；系统间差距很小时，可使用 DCR 或成对比较。

1. **刺激源**：不同系统使用相同的文本、参考说话人和采样率；同一系统内覆盖多样文本与说话人，保证数据的泛化性。
2. **听众**：选择与实验音频语言一致的母语人士。按照 P.808，每条音频至少需要 8 个有效评分，每个系统至少需要 96 个有效得分。
3. **环境**：保证耳机、场地安静程度等测试条件一致。
4. **实验过程**：采用盲测，隐藏系统来源并随机化顺序；设置陷阱题和重复题检查评分可靠性。
5. **实验后处理**：先剔除无效评分，再使用 ICC 等指标计算听众间一致性，同时检查重复样本的一致性。报告系统 MOS 时，除均值外，还应报告有效票数、标准差和 95% 置信区间。

### 8. 10 个人评分时，如何评价可靠性、处理稀疏评分并计算系统差异的置信区间？

这个问题本质上是在计算 inter-rater reliability（IRR）。

在整体层面，可以使用 ICC 检验评分一致性。ICC 大于 0.75 时，可认为数据具有较好的一致性；如果 ICC 很低，说明评价标准可能存在歧义，不能直接把这 10 个人的评分视为可靠数据。

在个人层面，可以使用留一法：对每位评分者，计算其评分与其余评分者平均分之间的 PCC。一致性明显偏低时，说明该评分者可能不具备足够评价能力或没有认真评分，应考虑剔除其数据。

如果每个人只评价了一部分样本，但评分者之间仍有足够重叠，可以采用支持部分评分设计的 IRR 方法。例如对每位评分者，只在其实际评价过的样本集合上，计算其评分与排除该评分者后的群体平均分之间的 SRCC，再对所有评分者的结果进行汇总。

比较系统 A 与 B 时，如果同一批人分别给两者打 MOS，可以构造配对差值 \(d_i=B_i-A_i\)，并为差值均值计算 95% 置信区间：

\[
\bar d \pm t\frac{s_d}{\sqrt{n}}
\]

如果整个区间都大于 0，则说明 B 相对 A 具有稳定优势。对于 A/B preference，可以统计选择 B 的比例及其置信区间；对于 CCR，可以在 \(-3\) 到 \(+3\) 的相对评分上计算 CMOS。若正值代表 B 更好，且 CMOS 的 95% 置信区间整体大于 0，则 B 显著优于 A。

### 9. FAD 是什么？它使用什么特征评价音频？

FAD 用于衡量生成音频集合与真实参考音频集合之间的感知分布差异，可以把它理解为音频领域中类似 FID 的指标。更严谨地说，它不是直接测量绝对“真实度”，而是衡量两批音频在特定神经网络特征空间中的接近程度。

首先使用 VGGish 或其他音频编码器，把每条音频映射为高维 embedding；然后分别统计生成音频和真实参考音频 embedding 的均值与协方差；最后计算两个分布之间的 Fréchet 距离。FAD 越低，说明生成音频的整体特征分布越接近真实参考音频。

这里使用的并不是 F0、MFCC、音色等人工命名的单一特征，而是神经网络学习到的隐式表征。

### 10. 一个 FFN 层有多少参数，会占用多少显存？

按只有一层隐藏层的普通 FFN 估算，若输入、输出维度均为 \(d\)，默认中间层维度取 \(4d\)，参数量由两层线性变换的权重和偏置组成：

\[
N=d\times 4d+4d\times d+4d+d
\]

仅计算权重与偏置时，显存约为：

\[
\text{Memory}=N\times\frac{\text{precision bits}}{8}
\]

例如 \(d=1024\) 时，中间层维度为 4096。实际训练显存还需要额外考虑梯度、优化器状态和激活值。

### 11. LoRA 能减少多少参数？如何选择 rank？

rank 主要根据任务复杂度选择：

- **简单任务（\(r=4\) 或 \(8\)）**：适用于基础格式对齐、语气调整或简单文本分类。这类任务不需要注入大量新知识，较小的 rank 通常足够。
- **复杂任务或知识注入（\(r=32\)、\(64\)，甚至 \(128\)）**：适用于医疗、代码生成等垂直领域知识注入，或复杂逻辑推理对齐。rank 太小容易欠拟合，实践中可以从 32 起步，再根据验证集 Loss 决定是否提高到 64。



## 捷通华声

### 1. 使用 LoRA 微调时，应该微调哪些层？

对于风格迁移等简单任务，只微调注意力中的 \(W_Q\)、\(W_K\) 等模块通常已经足够。对于较复杂的任务，主流做法是采用 `all-linear` 策略，也就是微调所有线性层，包括注意力模块中的 \(W_Q\)、\(W_K\)、\(W_V\)、\(W_O\)，以及 MLP 中的 `gate_proj`、`up_proj` 和 `down_proj`。

### 2. 如何降低人类主观倾向对评分的影响？

主观评分一定会受到个人倾向影响，无法完全消除，只能通过实验设计尽量降低：

- 统一试听环境和评分标准；
- 随机打乱样本顺序；
- 设置足够多的评分者；
- 使用重复样本或陷阱题筛除不认真评分的参与者；
- 最后使用 ICC 等组内一致性指标判断评分者之间的一致性。ICC 越高，说明这批主观评分越稳定、越可信。

### 3. 自建 CUC-TTS 数据集时，克隆人声和提示语如何设计？

先招募 10 位说话人，每人录制一小段声音。这段录音不作为最终评测数据，而是作为 TTS 模型的参考提示，相当于告诉模型要模仿哪位说话人的声音。

随后为每位说话人准备 10 句新文本，让 13 个 TTS 系统都基于同一段参考声音合成这些文本。最终每个系统生成 100 条语音，13 个系统共生成 1300 条。所有系统使用相同的说话人与文本条件，使系统间比较更加公平。
